## Speech-to-text

The public OpenRouter transcription catalog currently includes `microsoft/mai-transcribe-2` and `openai/whisper-large-v3`. The former's endpoint record identifies Azure. The latter lists DeepInfra, Together and Groq. Endpoint metadata contains generic parameters and is not sufficient proof of transcription timing/format support. Scribe was absent from this fetched catalog; that observation is not a claim that ElevenLabs has no transcription API. [STT catalog](https://openrouter.ai/api/v1/models?output_modalities=transcription), [MAI endpoints](https://openrouter.ai/api/v1/models/microsoft/mai-transcribe-2/endpoints), [Whisper endpoints](https://openrouter.ai/api/v1/models/openai/whisper-large-v3/endpoints)

Microsoft documents Polish support, word timestamps, verbatim or cleaned transcription and optional speaker segmentation for MAI-Transcribe 2. It explicitly labels the Azure feature public preview, without an SLA, and does not recommend that preview for production workloads. These caveats must be disclosed if Kiero chooses it as its first alpha candidate. Upstream capability and published quality claims are not a measured result on construction recordings. [Microsoft documentation](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/mai-transcribe)

OpenRouter documents `verbose_json`, segment/word timestamps and an MAI-Transcribe-2 example. Its multipart route is limited to 25 MB; processing timeouts require segmentation of long jobs. Several chat routing fields, including provider allowlists, do not apply to STT. Kiero cannot enforce a Whisper serving-provider shortlist by copying its chat settings. Request and validate actual timing fields on every selected route. Unsupported verbose formats may fail with 400. [STT API guide](https://openrouter.ai/docs/guides/overview/multimodal/stt)

Accepted Q205: evaluate MAI-Transcribe 2 first, with Whisper Large V3 as the designated backup, both via the dedicated OpenRouter endpoint and the existing application key. The owner accepted MAI's disclosed preview status only as a candidate requiring the existing quality/availability proof. Preserve verbatim speech, self-corrections and uncertainty; do not turn transcript cleanup into a change to the source. Validate timestamps against the original audio. Segment long recordings without a product duration cap, retaining one source and original-time offsets. Use supported processing encodings and prove conversion/segmentation with actual mobile formats; provider documentation does not prove every incoming browser codec passes through unchanged.

The STT fallback is application-owned bounded orchestration, separate from the chat model chain. A new attempt can call the approved backup for failed/unusable extraction. Do not describe a successful but uncertain phrase as an outage or keep sampling until a desired amount appears. Both models must pass critical name/amount/date checks. Partial segment outputs remain protected extraction artifacts; record each segment's model/provider and assembly version. Do not publish a complete transcript when segments are missing or silently reinterpret dependent memory after replacing an extraction version. Failed routes preserve the playable source and pending state.

## Semantic retrieval

OpenRouter exposes a separate embedding model catalog and `/api/v1/embeddings`. It currently lists `qwen/qwen3-embedding-8b`; endpoint records list Nebius, DeepInfra and SiliconFlow. Catalog context is 32,768 tokens, with one endpoint limited to 32,000. Neither generic `supported_parameters` nor model presence establishes that every provider honors reduced dimensions or optional retrieval instructions. [Embedding catalog](https://openrouter.ai/api/v1/embeddings/models), [embedding API](https://openrouter.ai/docs/api/api-reference/embeddings/create-embeddings), [Qwen endpoints](https://openrouter.ai/api/v1/models/qwen/qwen3-embedding-8b/endpoints)

The Qwen model card specifies multilingual retrieval, dimensions up to 4096 and query-side task instructions. Document text and query text use different preparation in its examples. Convex supports vector dimensions from 2 to 4096 and returns candidate IDs/similarity scores from actions; records may change before subsequent hydration. These facts support an integration candidate, not a Polish retrieval-quality claim. [Qwen model card](https://huggingface.co/Qwen/Qwen3-Embedding-8B), [Convex vector search](https://docs.convex.dev/search/vector-search)

Accepted Q206: start with Qwen3 Embedding 8B through OpenRouter and Convex-owned vectors. Use the native 4096-dimensional representation as the initial proof baseline; any reduction needs measured retrieval evidence and a versioned index change. Store vectors separately from ordinary UI records. Embed bounded source-linked text and relevant findings with tenant ID, exact source/revision identity and preparation version. Do not needlessly embed one entire company transcript or return vectors to browsers. Apply the accepted typed/current queries first, full-text and semantic candidate retrieval where needed, then current permission/source/revision checks.

A semantic index is rebuildable derived data. A new model, incompatible provider implementation, dimension or text-preparation version requires separate generation and verified cutover, not mixing old and new vectors even if their lengths match. Background writes recheck the input revision. Deleted/withdrawn content becomes ineligible immediately and its derived vectors follow the accepted deletion policy. During embedding outages preserve typed and full-text retrieval and expose incomplete semantic coverage where relevant; absence of a semantic hit is not proof that a fact does not exist.

## Releases and PWA updates

Cloudflare supports serving static assets with Workers. Convex documents production/preview deployments and schema enforcement against existing stored data. These services do not create a cross-provider atomic release transaction. Choose and test an application release protocol rather than assuming one command upgrades all clients and ongoing jobs simultaneously. [Static Assets](https://developers.cloudflare.com/workers/static-assets/), [Convex production](https://docs.convex.dev/production/overview), [deployment configuration](https://docs.convex.dev/production/project-configuration)

Accepted Q207: GitHub Actions builds/tests a pinned release, deploys isolated staging with synthetic data, and exposes a manually triggered production release. Serve the built PWA through Workers Static Assets. Deploy compatible backend expansion first, migrate data in resumable batches, update clients and only later remove obsolete fields/handlers. Preserve old pipeline executors or provide an explicit compatible migration for in-flight jobs; merely storing their version number is insufficient. Secrets are environment-scoped and never enter public assets. A release records source revision, package lockfile, schema/migration and pipeline versions. Check a recent complete backup before data migration. Recover a bad release with compatible code rollback or a forward fix; do not automatically restore an old database and discard new user data.

Accepted Q208: a PWA update waits until recording, editing and sending have reached a safe point. Show a Polish update prompt and persist the draft before activation/reload. Never force reload during capture or discard local upload progress. A stale unsupported client is told to update while its draft remains recoverable; security revocation still acts immediately. Cache only the application assets under an explicit version policy, and preserve the accepted private-data/session cleanup behavior. Verify update races on real mobile browsers, including old open tabs, changed local-draft schema and interrupted uploads.

These choices define behavior to prove. They do not authorize a deployment, migrate existing data, create a GitHub workflow, or assert that source capture, compatibility, privacy and recovery checks have passed.
