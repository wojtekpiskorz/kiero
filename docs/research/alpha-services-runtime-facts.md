# Alpha email, media runtime and service plans

Checked on 2026-09-08. The owner explicitly accepted Resend in Q209 and the media runtime in Q210. In Q211 they subsequently accepted the revised Free-first recommendation, usage-based Starter when sufficient, Professional when its features/capacity are needed, and deferral of native Convex log streams. The initial Professional-from-start recommendation was superseded. Existing choices include Convex Auth, Cloudflare hosting, an EU Container backup exporter, R2, Axiom and the retained-media policy. No service was purchased, provisioned or configured.

## Email delivery

The Convex Auth OTP guide includes a custom `Email` provider using the Resend SDK and a server-side `AUTH_RESEND_KEY`. It supports selecting the sender and message body. Its sample code lifetime and demo sender are examples, not new Kiero product decisions. The real application needs a verified sender/domain and the accepted authentication semantics. [Official OTP guide source](https://github.com/get-convex/convex-auth/blob/main/docs/pages/config/otps.mdx)

Resend's current pricing table lists a 100-email daily limit on Free and three custom domains. Confirm the remaining quotas during provisioning and track delivery/rejection results. Do not treat a successful API request as proof the user received a code. [Resend pricing](https://resend.com/pricing)

Accepted Q209: use Resend for Polish login codes and firm invitations, starting with Free for the small alpha. Use the same application-controlled sender and delivery integration. Upgrade when verified quotas require it; preserve the existing invite lifetime, explicit linking and session rules. The provider must not silently change the sign-in contract.

## Media execution

Cloudflare documents materializing an Images binding transformation into R2 and requires Images Paid for that tutorial. Paid transformations can operate on externally stored images. Current pricing includes 5,000 unique transformations each month, then $0.50 per 1,000; Images-hosted storage is a separate charge and is not required for this R2 design. The binding's input/capability limits and retained-original exception still apply. [Upload transformation tutorial](https://developers.cloudflare.com/images/tutorials/optimize-user-uploaded-image/), [Images pricing](https://developers.cloudflare.com/images/pricing/), [Normalization constraints](media-normalization-facts.md)

Cloudflare documents Containers with EU jurisdiction placement. FFmpeg documents independently packaged segments and segment lists with source timing information. Those capabilities support a candidate for converting actual browser recordings and producing bounded STT requests; they do not prove codec support, exact sample offsets or absence of gaps in Kiero's pipeline. [Jurisdictional placement](https://developers.cloudflare.com/changelog/post/2026-04-05-regional-placement/), [FFmpeg segment muxer](https://ffmpeg.org/ffmpeg-formats.html#segment)

Accepted Q210: use the Images binding for ordinary photo normalization and an EU Cloudflare Container runtime for FFmpeg audio conversion/segmentation and background firm-export assembly. Convex owns canonical job state, retries and domain publication. Containers execute scoped jobs with durable outputs/checkpoints and bounded resources; a crash cannot convert a partial output into completion. Stream large transfers and select instance resources from measured needs. Keep the media/export runtime separate from the backup executor's deployment key and backup bucket permissions, even if build tooling is shared. Unsupported photo conversion retains the accepted original exception. Audio conversion for processing must not silently replace the retained source.

## Plans and costs

Convex Professional currently costs $25 per developer per month and includes log streaming and daily backups. Tester/end-user accounts are not developer seats. This plan supports the already selected native log-stream path; it does not by itself satisfy Kiero's hourly recovery target. [Convex pricing](https://www.convex.dev/pricing)

Workers Paid has a $5 monthly baseline with included usage. Containers add metered CPU, provisioned memory/disk, network and associated Worker/Durable Object usage after allowances. Sleeping behavior affects charges; a container's provisioned memory/disk differ from actual CPU usage for billing. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Containers pricing](https://developers.cloudflare.com/containers/platform/pricing/)

Axiom Personal currently permits one user, three datasets, three monitors and up to 30 days of retention, with usage limits. Owner email alerting is supported. Its free tier cannot be described as unlimited monitoring. [Axiom limits](https://axiom.co/docs/reference/limits)

### Free-first Convex revision for Q211

The current Free/Starter feature list includes auth, actions, cron, full-text/vector search, preview deployments and selectable region. Free uses hard resource caps. Starter has no fixed subscription and allows usage beyond its included allowance, while sharing Free's S16 deployment class. Professional adds native log streaming and S256 capacity. A usage limit alone therefore does not necessarily require Professional. EU resource pricing differs from the US examples; current limits documentation specifies a 1.3 multiplier. [Convex pricing](https://www.convex.dev/pricing), [limits and plan behavior](https://docs.convex.dev/production/state/limits)

Native Convex log streams require Pro. Recent platform logs remain accessible through the dashboard/CLI, but this does not supply the previously discussed 30-day Axiom history. Convex actions can make external HTTP requests, and Axiom accepts application events through its ingestion API. These primitives support explicit redacted application telemetry; they are not an equivalent export of all platform function executions, failed mutations or console output. [Log streams](https://docs.convex.dev/production/integrations/log-streams), [actions](https://docs.convex.dev/functions/actions), [Axiom ingestion](https://axiom.co/docs/restapi/ingest)

The selected external backup job also consumes Convex resources. Documentation charges backup generation against database/file bandwidth and storage. Free/Starter permit at most two stored native backups per deployment, and built-in daily/weekly scheduling requires Pro. CLI export and externally scheduled R2 copies must be proved on the exact chosen plan, including native artifact lifecycle and interrupted runs. R2 retention does not remove Convex export costs. With a 15-minute schedule, approximately 2,880 full snapshots occur in a 30-day month; even a small growing dataset can make export traffic the first reason to leave Free. Do not reduce the agreed backup frequency silently to fit quotas. [Backups and billing](https://docs.convex.dev/database/backup-restore), [CLI data export](https://docs.convex.dev/database/import-export/export)

Accepted revised Q211: start Convex Free. Before its caps would interrupt use, move to Starter if metered usage is sufficient, or Professional when native log streaming, higher capacity or another required Pro feature warrants it. No application/database rewrite is proposed for a plan change; verify the vendor's actual upgrade procedure during provisioning. Keep Workers Paid and the accepted external backup design.

Accepted amendment to Q204 during the Free phase: Axiom receives explicit redacted application events and Cloudflare diagnostics; native Convex platform log streaming waits for Pro. Preserve durable job/history records, audited GM access, the required failure/freshness/cost alerts and an external missing-health check. Thirty-day retention applies to diagnostics actually ingested, with the platform-log coverage gap stated explicitly. Implement only the small integration needed for those events; if equivalent operational alert coverage needs a separate logging system, upgrading is preferable. Alert delivery, stalled or aborted jobs, ingestion failure and current plan quotas remain proof obligations.

Start Axiom Personal if those alerts fit its three tested monitors, grouping processing/save incidents, recovery/health freshness and costs without losing incident context. Upgrade when coverage or usage needs it. Resend Free is accepted in Q209. The initial fixed-service base would be Workers Paid at $5 per month before usage, taxes and other services, not an all-in alpha estimate. Keep the accepted 400/500 PLN all-in alerts and soft budget. Free hard caps require proactive review and upgrade; a monitoring plan is not proof that writes can never hit a provider limit. No automatic paid upgrade or purchase is executed by this planning decision.

See the [architecture proof matrix](../mvp/architecture-proof-matrix.md). Runtime execution, service quotas, delivery and measured costs remain unverified.
