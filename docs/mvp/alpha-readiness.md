# Alpha readiness and handoff contract

Accepted by the owner in Q212–Q216. The subsequent two-package instruction permits the barebones core to be built in parallel with the later full UX/UI work. This is an acceptance contract and evidence plan; all implementation proof rows remain **NOT RUN** at handoff.

## Distinct outcomes

1. **Decision handoff:** agreed behaviors, architecture, the UX/UI brief and an executable core dependency graph are published. This closes the planning map.
2. **First real text loop:** two authenticated bosses can persist a source, observe real AI update project memory, inspect provenance and correct an agreement in the unstyled application. This is an early engineering checkpoint.
3. **Complete core qualification:** all agreed core behaviors have real implementations, reachable barebones controls and recorded integration/failure evidence. The implementation map ends with a precise handoff of this result to UX integration and alpha preparation.
4. **Alpha entry:** the intended user-facing candidate is integrated, the applicable readiness evidence is current, owner/operator rehearsal and tester onboarding are complete, and the owner accepts entry. Outstanding full UX/UI work is visible, never relabelled complete by a core-only result.
5. **Alpha outcome:** four weeks of actual use by both bosses are assessed under the existing [alpha contract](https://github.com/wojtekpiskorz/kiero/issues/3#issuecomment-5573718534). Synthetic cases and GM repairs cannot satisfy autonomous-use outcomes.

## Devices and environments

Required physical tests include an iPhone, an Android phone and the actual handsets of both testers. If both testers use one platform, add a device for the other. Exercise browser entry and installed PWA operation. Desktop scope is Chrome/Edge and Safari.

Before qualification, record device model, OS version, browser version, installation mode and relevant permission/storage settings. No currently unknown minimum version is asserted as supported. A version receives supported status after the required device tests pass. Desktop emulation supplements physical evidence and does not replace it.

Use isolated local/development and synthetic staging resources for implementation. The final integrated candidate supplies release/device evidence. Real user data and alpha production activation have their own explicit scope.

## Evidence register

Each case in the [architecture proof matrix](architecture-proof-matrix.md) has an owner, exact code revision, package and provider configuration, environment/device, input fixture, independently stated expectation, repeatable command or procedure, observed result and a link to redacted evidence. Record cost for metered work.

Use `NOT RUN`, `PASS`, `FAIL` or `BLOCKED` with a reason. An accepted requirement cannot become "not applicable" to hide unfinished implementation. A real scope change requires an owner decision and updates to the affected specifications and issues. A provider outage is recorded separately from wrong application behavior; neither creates a fictitious pass.

Critical failures block alpha entry: lost accepted sources, unauthorized data/access, corruption of a later correction, a wrong project/amount/date/commitment presented as established, and failed required recovery. Relevant integration, deletion and access invariants also require their stated tests. Cosmetic or minor convenience defects may remain in an explicit backlog with owner acceptance, provided the required workflows work.

The first text checkpoint and feature-local tests do not have to wait for every later proof. The final core qualification joins all P01–P12 evidence. If final UX integration changes a tested behavior, rerun the affected cases on that integrated candidate.

## AI entry criterion

Use the accepted 50-case corpus: 14 text, 16 voice, 12 image and 8 mixed follow-up cases. Each of three complete runs must achieve at least **48/50** correct case outcomes, with **zero critical errors** involving project, amount, date, commitment or source basis.

An appropriate clarification for ambiguous evidence is correct. Unnecessary clarification for clear evidence reduces quality. Correctness includes persisted facts, provenance, required questions and prohibited changes, not just a plausible answer. Report STT, image extraction, retrieval and final memory effects separately; an aggregate cannot conceal a critical failure. The independent answer key cannot be derived only from the model under test.

Report ordinary-source latency against the existing target: at least 95% complete memory processing within 60 seconds after full durable acceptance. Ordinary means text, one image or audio up to two minutes. Longer audio remains supported without a product duration cap and is measured separately. Google sync has its own 95% within 60 seconds target after a canonical change, conditional on available Google service and a working connection.

Version the corpus, prompts, schemas, provider routes and models. Changes rerun affected cases and relevant integration proofs; complete qualification records the three full runs of its actual candidate configuration.

## Rehearsal and entry

Before tester entry, the implementer and owner as GM exercise the complete application with a test company, two accounts and physical devices. Cover a normal working day, interrupted upload, unavailable AI, revoked access, PWA update and recovery. Run the previously accepted Google Calendar observation beyond one week in the background; accelerated clocks cannot substitute for credential-lifetime evidence.

After technical acceptance, onboard the bosses together: login, optional PWA installation and push permission, first source, retrieval of an agreement, and correction. Then start the four weeks of actual alpha use. Existing criteria remain unchanged: weekly ten real questions with at least 9/10 correct source-backed answers, independent use by each boss on at least three working days weekly in the last two weeks, the processing target, and no unresolved critical error before widening.

Budget remains observational: alerts at 400/500 PLN for total monthly infrastructure and AI, without automatic product shutdown at 500 PLN. Convex Free-first and later plan changes follow the accepted architecture. Q195's deferred formal privacy review remains deferred; this handoff adds no training-consent requirement.
