## Shared state checklist

Apply these states to every relevant UX ID instead of designing only the ideal path:

- initial and empty;
- loading and saving;
- locally drafted;
- durably accepted but processing;
- partially processed;
- current success;
- stale or superseded;
- conflicted or awaiting answer;
- permission denied, revoked or unsupported;
- offline or provider unavailable;
- retrying, unknown external outcome and reconciled;
- closed, canceled, withdrawn and permanently deleted;
- access lost while the view is open;
- mobile installed PWA, mobile browser and desktop browser.

## Coverage gaps to settle during full UX/UI work

These are presentation questions, not missing domain requirements:

- exact mobile and desktop navigation between company conversation, project memory, search, `Co teraz`, settings and admin;
- density and progressive disclosure for source evidence, revisions and agent changes;
- Polish microcopy for uncertain, conflicted, partial, failed and access-revoked states;
- accessibility behavior for recording, waveform feedback, image evidence regions, push prompts and dialogs;
- information hierarchy for company memory versus project-specific overrides;
- bulk operations, sorting and filtering that help two-boss alpha use without inventing new semantics;
- visual language and component library after the structural flows are approved;
- exact boundary between boss-facing recovery messages and the GM/operator panel.
