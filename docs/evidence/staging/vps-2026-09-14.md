### R9 verifier defect found by the live run (prerequisite repair, R9 lane)

`infra/release/verify-convex-target.mjs` refused the CORRECT staging target.
The credential-selected identity resolved to exactly the pinned deployment —
`type prod`, team `wojtek-piskorz-jr`, project `kiero-dev-core`, reference
`staging`, slug `fiery-raven-417`, `isDefault false` — but the comparison
failed on the `url` field alone:

- observed `url`: `https://fiery-raven-417.eu-west-1.convex.cloud...` (trailing ellipsis)
- expected `url`: `https://fiery-raven-417.eu-west-1.convex.cloud`

Mechanism (provider CLI 1.45.0 source): `node_modules/convex/src/cli/lib/deploy2.ts:458`
runs `showSpinner(\`Deploying to ${url}...${dryRun ? " [dry run]" : ""}\`)`;
in non-TTY CI the spinner text reaches stderr, and `parseConvexAnnouncement`
(`verify-convex-target.mjs`, the URL-line selection at the `deploymentUrlLines`
block) prefers the LAST line in its 5-line window matching `convex.cloud`, so
the spinner line beats the real `└─ <url>` announcement line. The URL regex
then captures the trailing `...` and the strict `url` field compare flags a
false mismatch (`region` also parses as null for the same reason). R9's local
probes ran on a TTY where this line never polluted the captured output.

The refusal itself was CORRECT behavior (refuse-first, no mutation); the
defect is that the gate cannot PASS in CI against the right target. Suggested
repair for the R9 lane (not made here — `infra/release/**` is not I8-owned):
prefer the `└─`-prefixed announcement line over generic URL-bearing lines, or
strip a trailing `...`/` [dry run]` marker before comparing. Until this lands,
every CI Convex deploy leg of every target blocks `target-verification-failed`
against a matching identity.
